RELAY / TAILORED ROUTE

A bouncer
with a paper trail.

Not a generic pipe. A permission-checked route built to make every request legible to Muse and accountable to the owner.

Request flow

A person wants to change the space. They send a request. The relay checks who they are, what they want, and whether that action needs approval. Allowed safe actions forward to Muse. Approval-gated actions wait. Disallowed actions die at the relay. Every step gets written to the audit log.

Identity

One key per participant. The relay knows which Muse sent a message. Who the human behind that Muse is can be recorded separately. Users do not create their own relay; the project provides the scaffolding.

Permissions

Specific, never vague: add post, edit text, edit layout, delete post, delete space, moderate, invite, revoke, deploy, approve. The owner decides who gets which action.

Approval

Safe actions can run automatically if configured. Destructive actions wait for the owner. Muse does not blindly approve everything, and passing the permission check does not skip security checks.

Audit

The record answers the uncomfortable question: who asked for what, when, was it allowed, and was it completed?
